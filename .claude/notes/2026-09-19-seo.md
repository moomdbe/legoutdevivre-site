## Mise en place Google Search Console

Accompagné l'utilisateur pas à pas (captures d'écran) pour :
- Créer un compte de service Google Cloud (`gsc-legoutdevivre-readonly`) et sa clé JSON.
- Vérifier la propriété `legoutdevivre.co` dans Search Console en **type "Domaine"** (pas préfixe d'URL), via un enregistrement TXT `google-site-verification=...` ajouté dans **Netlify DNS** (confirmé : le DNS du domaine est géré par Netlify, pas Cloudflare, malgré la présence d'un Worker Cloudflare du même nom dans le repo — vérifié par API Netlify : `legoutdevivre.co` est le `primarySiteUrl` du projet Netlify "legoutdevivre").
- Ajouter le compte de service comme utilisateur **Restreint** (lecture seule) sur la propriété.

Testé l'accès API (`searchanalytics.query`) avec la clé fournie par l'utilisateur, dans un environnement temporaire isolé (clé supprimée juste après le test, jamais committée). Résultat : accès confirmé, `permissionLevel: siteRestrictedUser` sur `sc-domain:legoutdevivre.co` (bien noter le préfixe `sc-domain:` requis pour une propriété de type Domaine, `https://.../` échoue en 403). Pas encore de lignes de données — propriété trop récente, normal.

**Stockage de la clé** : aucun outil (`create_trigger`, `create_session`) n'expose de paramètre pour injecter un secret en variable d'environnement pour les sessions déclenchées par une Routine. Solution retenue après vérification de la doc officielle (code.claude.com/docs/en/cloud-environments) : variable d'environnement `GSC_SERVICE_ACCOUNT_JSON` sur l'environnement cloud "Par défaut" (claude.ai/code → sélecteur d'environnement → Cloud → engrenage au survol → Variables d'environnement, format `.env`, JSON entouré de guillemets simples). Fait par l'utilisateur, confirmé. Limite connue et signalée à l'utilisateur : ces variables sont lisibles par toute session utilisant cet environnement (donc aussi la session design) — accepté car même compte des deux côtés.
